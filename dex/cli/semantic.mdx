## dex semantic define

Validate new semantic models or metrics, including with dbt's own parser, and store them as a plan. Refuses a removal. Repo-only.

<Accordion title="Usage and options for dex semantic define">

```text
dex semantic define [--edits-file FILE] [--definitions-file FILE] [--no-parse]
    [<intent>]
```

**Arguments**

| Argument | Description | Default |
| --- | --- | --- |
| `[<intent>]` | one line saying what the change is for |  |

**Options**

| Option | Description | Default |
| --- | --- | --- |
| `--edits-file FILE` | whole-file edits payload as JSON; '-' reads stdin |  |
| `--definitions-file FILE` | definitions written in place, as JSON; '-' reads stdin |  |
| `--no-parse` | skip validation with dbt's own parser |  |

</Accordion>

## dex semantic ossie

Validate whole Ossie documents at the paths semantic.ossie.files configures, then store a plan. `--from-metric-view` proposes the document from a Metric View file through dex's port of apache/ossie-converters. Needs the [ossie] extra. Repo-only.

<Accordion title="Usage and options for dex semantic ossie">

```text
dex semantic ossie [--edits-file FILE] [--from-metric-view FILE]
    [--name MODEL] [--dataset-metrics] [--into PATH] [{define,update,plan}]
    [<intent>]
```

**Arguments**

| Argument | Description | Default |
| --- | --- | --- |
| `[{define,update,plan}]` | define new documents, update existing ones, or plan a mix |  |
| `[<intent>]` | one line saying what the change is for |  |

**Options**

| Option | Description | Default |
| --- | --- | --- |
| `--edits-file FILE` | whole-document edits payload as JSON; '-' reads stdin |  |
| `--from-metric-view FILE` | propose the Ossie documents from these Metric Views |  |
| `--name MODEL` | the model and fact dataset name |  |
| `--dataset-metrics` | write fact-only measures as dataset metrics |  |
| `--into PATH` | output path (default: beside the configured files) |  |

</Accordion>

## dex semantic databricks

Validate whole Metric View YAML files at the paths semantic.databricks.files configures, with dex's port of the Metric View YAML 1.1 rules, then store a plan. `--from-ossie` proposes the view from an Ossie document through dex's port of apache/ossie-converters. Needs the [metric-views] extra. Never deploys a view and opens no workspace connection. Repo-only.
